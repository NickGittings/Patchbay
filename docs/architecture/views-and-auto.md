### Views

Auto mode (`lib/auto.ts`, `components/auto/`) is a per-worktree frontend controller: plan → implement → validate → review ⇄ fix → merge gate → merge. Light/Standard/Thorough presets set the fix budget, severity floor and validation; Advanced overrides and ask/automatic merge are chosen per run. Each agent stage launches its own preset (`AutoRun.agents`, else `device`, the only one older runs record; `agentFor`), seeded in the dialog from the project's agent roles; the implement stage still hands off the plan stage's planner. With several reviewers (`AutoRun.reviewers`), the review stage launches them in one round (`startReviewAgents`), tracks the first and owns the rest (`laneSessions`, stopped when the stage ends, on Stop, Skip and settling); its completion waits while another reviewer still works, before judging the combined verdict. Every session a run tracks is an `AutoLaunch` (session id, start time, launch request, review lane, turn): the primary in the run's `session*` fields, reviewers beside it in `laneSessions`; `launches`/`track` convert between them, so a reviewer taking the lead just moves to the front. Auto owns a launch while its process generation is the one it launched: its start time, else its launch request is still its record's latest (`owns`), and `stopOwned` rechecks that as it stops each one. `startReviewAgents` always sends a round id (also for one reviewer) and returns each started reviewer's session id, request id and lane (`started`), adopting after its one reconciliation a start whose lost reply the backend couldn't recover yet; the run records them and `reviewRound`. `observe` judges every tracked session the same way for the drive and Resume (failed: forgotten, stopped, relaunched, or exited or idle before finishing its turn; asking for input counts as being in a turn, and only the reviewer an input wait opened counts as stopped while it waits), and `roundStatus` classifies Auto's round from those and the findings, matched by lane: `superseded` when the latest round isn't `reviewRound` (someone started a newer review), `broken` when a reviewer failed before writing or an untracked launch was never confirmed, `complete` once every reviewer finished its turn or failed after writing, else `running`. The drive pauses on a superseded or broken round with what to do, and stops tracking reviewers that failed after writing, also during an input wait (it follows a tracked agent while the run is running or waiting on you; Pause or Stop end that). Resume (refused while the session service is disconnected) keeps a running or complete round's reviewers that still work. It ends a broken round: it stops the round's reviewers it owns and infers the stage again, so it reviews anew, but asks the user to close any it can't prove it started instead. A superseded round stops only what Auto owns; the newer review's sessions stay and inference follows them. A review launch the service refuses with `session::TERMINAL_RUNNING` (↔ `types.ts` `TERMINAL_RUNNING`, matched by exact text) pauses rather than failing the run. It can infer the next stage from manual work, pauses for input or interruptions, and requires installed authoritative status hooks. `TaskWorkspace.auto` is UI state in the workspace layout, never `patchbay.json` or `dirty`; every unfinished restored run is Paused with its pause kind until Resume (done, stopped and failed runs stay so) and keeps tracking, and owning, the agent it launched, which outlives the app in the service. A task's inferred goal comes from its own plan only. A new worktree (never an attached one) made from Plan (Planner scope's New task, the rail's Worktree panel while Plan is shown, Implement's New worktree…) or from Auto's needs-worktree prompt (`seedAutoTask`) starts with a copy of the nonempty, uncut project plan, written only while it has none (`seedNewTask(then, { copyPlan: true })`, best-effort, before the dialog's follow-up runs); Implement still copies the current project plan over it. A start of a terminal a run still tracks sends the run's recorded brief (`AutoRun.sessionBrief`, and a planner's `plan` kickoff, whose resume command drops its prompt) so Restart's fingerprint matches. The plan stage finishes only once the project plan or proposal differs from when the planner launched (`planMark`). A new run on a branch whose earlier work is already merged plans its goal instead of ending as Done; the dialog previews with the same inference. Automatic merge needs a HEAD whose current findings leave nothing to fix at the run's severity floor (`mergeableHead`); otherwise the merge gate asks, and skipping a fix whose budget ran out goes there too. An agent whose stage didn't finish (an incomplete merge, an unreadable verdict) stays running and tracked for the user. Validation runs through `lib/actions.ts` `graphActionIn` and pauses when the backend refuses it. A run records its branch (`AutoRun.branch`) when it starts and judges only that branch: when its worktree has another one checked out, a running run pauses and the approval wait reports it. The approval wait shows merge-status errors in `AutoRun.gateError`, never in its reason, and keeps retrying. A merge agent that ends, is stopped or forgotten, while waiting or not, first checks Git, so a merge finished by hand ends the run Done; every path that finds the branch integrated (`settleIntegrated`) also stops an owned agent still running, since a finished run offers no Stop. Start is refused only while a launch may still attach its agent; a drive of a stopped run acts only on its own `runId`. Snapshots read `merge_outcome` only while merging or inferring the stage of a reviewed or merged branch (a fresh branch is trivially an ancestor). Auto reviews against the merge destination when it is a branch, resolves the project folder to the current worktree, and treats the planner as its own only while planning or tracking it. Validation without a validation terminal is skipped, not failed. Validation failures (`AutoRun.validationFindings`) keep a review from reaching the merge gate until a validation passes or the user skips validation; while they remain, finished work and resumed changed branches go to Validate whatever the effort's validation setting, and skipping or resuming an interrupted fix keeps them. A fix round counts once its launch returns a session, even if confirming it fails. The main window's `followAuto` watches raw agent reports and polls findings; updates are pinned through `patchTask`, and launches pause when the worktree is not driveable (see [Scheduler](scheduler.md)). Review completion requires a fresh structured verdict, and merge completion is checked in Git. `smoke:auto` uses a fake agent writing hook journals, findings, a fix commit and a real merge on scratch worktrees.

The main window switches between Navigation (the canvas, with no component list since unified search finds components (Enter runs a component named exactly what was typed first, else the first result of the priority group, never another group's, so late file results can't change it, `lib/search.ts`; `focusComponent` in `lib/navigation.ts` centers one, after a view switch too, dropping React Flow's pending initial fit, and `withoutHierarchy` gives an old layout's list width to the canvas); nodes show changes, map issues, a dashed outline when they depend on a changed component (`lib/plan.ts` `affectedIds`), and a chip per role agent (Plan/Build/Fix/Review/Merge) whose hook activity wrote their files (`activity.ts` `writeActivity`; reads don't count), pulsing for ten seconds (`lib/activity.ts` `componentActivity`, published by `lib/mapActivity.ts` while Navigation or Chat's map is mounted, re-run on session changes and by a timer only while a pulse is live; a chip reveals that session); the Inspector's Files tab marks changed and agent-written files (root-relative, `../` for external components, as `activityFile` names them) and opens a changed file's diff below the tree; the inspector while `showsInspector` — the per-project `inspector` (opened or closed by the user) or else an existing selected component or link — and the dock while `dockTabs` lists running sessions (plus exited ones in `dockKept` — revealed with `setActiveSession`, failed, or exited while active — until closed there) or a dock extension view exists, both in `lib/panels.ts`; hidden panels collapse rather than unmount, so their tabs keep their state, since react-resizable-panels can't add a panel to a mounted group and the canvas must not remount, and reopen at the size remembered under `panels['App-open']`), Plan (highlighted canvas above a project-level planner dock, with New task in Planner scope), Implementation (labelled **Build** in the UI; ids, types and storage keep `implementation`; a controls row with Add terminal and New task, and an ordered component list with a visibility flag per entry, reached with Plan's "Implement →"; click a pill to toggle its visibility, × to remove it from Implementation, and "Add component…" to append one; Plan highlights update the same list and unhighlighting retains a hidden pill; each component's tiled terminals with an "+ Add terminal…" select that saves to the map, a per-tile maximize and × that asks for confirmation, waits for pending launches/restarts and stops every worktree copy before removing the saved terminal, and a pop-out button on each component's header; `revealTerminal` sets the UI-only `revealed`, which shows its component after the highlighted ones without joining them and un-maximizes other tiles), and Review (every changed component's files and diffs, plus project files, filterable by component chips and following the rail's Worktree panel; the components that may be affected, and whether each one's task terminals ran since the change: `ReviewView.tsx`, `lib/review.ts`). Review offers “Review branch…” then “Merge into…”, with both sessions in `ReviewAgentPanel` (`lib/reviewAgents.ts`, reserved `@review`/`@merge` scopes). Findings render as cards, never raw text (`components/findings/FindingsPanel.tsx`: verdict, severity filters, per-reviewer sections; `lib/findings.ts` splits the text into `[severity]`-tagged findings and `path:line` refs leniently, for display only, since counts come from the backend verdict; `lib/markdown.ts` renders their Markdown as elements, never HTML). Review's Findings button shows the source branch's findings in place of the diff, where a ref to a changed file opens its diff with a way back; Auto's utility panel shows the verdict and opens it there (`reviewFindingsFocus`, UI only). Review sessions also have a read-only Findings toggle, which keeps the terminal mounted underneath; the title reports whether findings cover HEAD and every uncommitted change in the reviewed worktree made before the review started (`Findings.edited_since_start`, computed in core, so the status never depends on Review's change list). Review bases include local branches (`git_branches` ↔ `gitBranches`). Findings refresh on focus and review exit, and every 5s while shown (Review's source branch, or while a review of the panel's worktree is busy or its Findings toggle is open); the merge dialog reports their status without blocking. Hide/Show agents, Sessions and Attention recover either scope without moving the active task or adding a Navigation dock tab. Panel layout ids remain `ReviewView-merge` and `ReviewView-merge-terminal`. Fixes stay in Implementation: a finished review with nonempty saved findings offers "Fix in Build →" (`lib/reviewHandoff.ts`), which asks the backend for the review's task (`review_fix_task`, `null` for the project folder, selected exactly; refreshing the task list first if it lacks that task or lists it as missing), activates it, and starts a fresh root agent with a preset of the reviewer's provider (session records keep no preset id), else `agentDevices`' first. The button waits while any review of that worktree may still be writing (`reviewWorktreeBusy`: running unless it reported the end of its turn, `review` (a self-reported one only until output resumes more than 2s later, since a follow-up turn doesn't change it), or its provider hooks confirmed it `idle`/`ended`; a permission prompt, a stale or unconfirmed `idle`, or no report at all keep it busy until exit), since interactive reviewers keep running at their prompt. A launch that fails removes the fix tile and switches back to the previous worktree, unless the user moved on. Only that agent receives the findings of the reviewed branch and the fix prompt; the view switches after launch succeeds if the user is still in that worktree, and unknown worktrees must first be added as tasks. `lib/diff.ts` parses a patch into hunks with old/new line numbers for `DiffView`. The shared pieces live in `components/changes/`; Review, the pop-out's Changes tab and Chat's diff step through changed files with ↑/↓ (and ←/→) in a change list, ←/→ in a focused diff once it can't scroll further that way, and the diff header's ‹ › buttons (`lib/changeNav.ts`; Review skips collapsed groups); with focus on body, `useStepKeys` steps only while the last click landed in the list or a diff (or before any click), so arrows still scroll the chat thread or findings; `ChangesPanel` also backs the pop-out's Changes tab. Change lists and diffs reload whenever the store's `gitChanges` object is replaced, which happens on every Git refresh. `view`, `highlighted`, `implementationComponents` (ordered ids and visibility), and `planStartedWith` are persisted in the per-user workspace layout; they never change `dirty` or `patchbay.json`. Plan terminals come from agent devices and use the reserved `@plan/<terminalId>` session scope. `plan_start` / `plan_context` in the Tauri adapter ↔ `planStart` / `planContext` in `lib/ipc.ts`; `context::plan_session_spec` launches at the repo root with the scoped briefing (Claude and Codex also get `--add-dir` for in-scope or nearby components outside the root), while `policy::Scope` supplies either a component or the planner's real component set to policy checks. `TerminalGrid` is shared by Implementation and component pop-outs. Navigation, Plan, Implementation (Build) and Review use ⌘1–4; open projects are listed in the rail's Project panel (`ProjectSwitcher`: switch, close, Open folder…; closing asks first while a project has running terminals); a saved `tasks` view falls back to Navigation. All views use the same session and xterm registries, preserving scrollback and window ownership.

Agent roles (Settings → Agent roles…, `lib/agentRoles.ts`) assign a preset to plan, implement, review, fix and merge per project: `agentRoles` lives in the workspace layout, never `patchbay.json` or `dirty`. `roleDevice` falls back to the caller's default (the planner's agent for Implement, the reviewer's provider for Fix), else the first preset. Review and Merge dialogs preselect the role, Plan shows its planner tab until one is picked, and an explicit preset (Auto's) wins over the role.
