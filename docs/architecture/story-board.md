### Story board

Navigation's Map / Stories toggle is a canvas sub-mode, persisted per project as `storyBoard` in the workspace layout; it never dirties the map or adds another View. The toggle also shows in Chat mode, where the board takes the place of the chat's map and Chat stays open (`setStoryBoard` switches `view` only outside Chat). The map stays mounted while the board is open. Epics contain features; features contain stories, and stories can also be unassigned. Items and acceptance criteria live in `stories.json` beside the per-user task store in the common Git directory, shared by worktrees and never committed. Features require an epic: keeping an epic's children during deletion requires moving its features first; deleting a feature without cascading leaves its stories unassigned.

`lib/stories.ts` owns hierarchy, status derivation and the Plan / Auto actions. A story planner uses the plan role and a backend-owned Story section (ancestors and descendants included). The project layout remembers `planStory` and `planStoryTerminal` for that session's Restart; a plain planner start preserves them, and only an explicit story start replaces them. Plan shows a dismissible pending-story chip; only the original terminal receives the Story briefing. New worktree in the editor or Plan links immediately at creation. Implement links whichever planner hands off the pending story, skips a link already pointing to that task (preserving `task_head`), and clears the pending story after successful linkage. Auto carries its pending story id with the draft through new-worktree creation, linking it only after a successful run start. Cards derive review and merge stages from unfinished Auto stages or the newest matching review/merge/root session by `snapshot.startedMs`; a later fix returns to Building. These display stages do not change stored `StoryStatus`. Cards follow live worktrees, finished Auto runs and verified recorded merges; parent statuses roll up from children, while explicit Done stays Done. A card linked to a worktree also shows that worktree's Auto stage and status, for the item's own run or any unfinished one. A fresh branch at its base is not a completed merge. `smoke/stories.js` exercises creation, briefing, worktree linkage, goal prefill and returning to the map.
