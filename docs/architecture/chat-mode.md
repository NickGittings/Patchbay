### Chat mode (opt-in)

The rail's **Chat mode** toggle (`simpleMode`) opens one worktree conversation beside Navigation's read-only map or story board. The last Full view stays saved. Rail view buttons and Cmd/Ctrl+1–4 leave Chat for the requested Full view. Story Plan and notification View stay in Chat. `revealTerminal` selects the related worktree/session and scrolls to that agent's latest block without changing views. Chat uses independent `App-simple` / `App-simple-open` panel sizing; old Navigation layouts gain a collapsed chat slot through `simplePanelLayout`.

`lib/simple.ts::thread` projects a chronological timeline, grouping consecutive prompts and replies under plain agent headers. `sections` groups stage attempts, collapsing older steps to role, summary and time while the latest stays expanded; revealing a session opens its section. `lib/simpleFlow.ts::flow` scripts planning, build, review, fix and merge narration and prompts from sessions, actions, artifacts and Auto state. Simple calls no model. Agents' final messages come directly from Stop hook `last_assistant_message`, capped at `agent_hooks::REPLY_LIMIT` (16 KiB) on a UTF-8 character boundary. `Tracker` accepts replies under its generation, journal sequence, conversation and turn checks, retaining the newest 20 and emitting `TerminalEvent::Reply` while the process runs; each event names the sequence of the run's previous reply (`previous` ↔ `TerminalEvent` `previous`, null for the first). `Snapshot.replies` restores this window. Session lists carry only `lastReply`; `sessions.ts` remembers per session how far this window's replies are complete (`replySnapshots`), extends that with a live reply whose `previous` is the covered one, and reads a snapshot (`fetchReplies`, through `sessionFromSnapshot`, the one snapshot→`SessionState` conversion, which takes a listing's `interrupted` only for the run it lists) only when `lastReply` is past it. Session protocol 11 added replies, 12 their `previous`, and 13 explicit forced prompts (this checkout already used 10 for activity/prompts); the retirement handshake handles older services.

`TaskWorkspace.simple` holds `{ startedMs, log }`, including the project-folder workspace keyed by `''`. Prompt entries retain exact transmitted text, mentions, session and generation; only prompts and entries that start or resume a run (plan, implement, review, fix, merge, resume) may claim it, never Auto controls. A launch's entry goes through `simpleActions.ts` `logLaunch` with its launch request id (`startTerminal` resolves to it once the session started, the handoffs return it beside the session id, reviewers carry theirs, and resume and merge pass their own): `launchedRun` claims the run of the record whose latest `requestIds` entry is that request, from the store's records, else the service's list (applied to the store when newer), and otherwise no run; no clock is compared, so a stopped, pre-launch or later run is never claimed. Chat resumes log their claim before reconciling and then persist the replies already held. `SimpleState.version` (`SIMPLE_VERSION`) marks logs saved by this scheme; restoring an older one gives each run-less claiming entry the run of its session's next entry naming one, in `boundedSimpleLog`'s order, else none (`restoredSimple`). Prompts and successful actions are retained in the conversation log. Reply text is capped at 16 KiB per reply and 128 KiB per chat, retaining the newest replies (`boundedSimpleLog`, which orders the log by time and journal identity first). No cursors are persisted: a reply evicted by the budget is older than every retained one, so re-adding it after a restart (from a snapshot's last 20) trims it again and `logSimple` leaves the log unchanged; `thread` applies the same bound to the replies it merges. `simpleReplies.ts` persists replies during ingestion even while Chat is unmounted, deduplicating by session/generation/sequence; reconciliation repeats it for a shown session only when its key (run, reply sequences and receiving chats, `persistChangedReplies`) changed since the last pass. Shared planner replies enter only conversations that used that run (`ownsPlanner`: a claiming entry with that exact generation; an entry without one claims no run), and only such a run shows in a chat's thread or takes over its recipient with an input wait (`thread`'s `foreign`, passed to `selectRecipient`); another chat's run is no agent of this one in `flow`. `flow` takes the thread and recipient its caller already computed. A provider-confirmed `idle` without a turn ends an agent's work unless this chat launched or prompted that run and its turn hasn't begun; reviewers follow `review.ts` `reviewerBusy`, the rule `reviewWorktreeBusy` uses. `restoredSimple` validates reply identities. Build from the project folder offers New worktree and copies entries since planning began into that worktree before handoff. Story linkage happens before Build; `implementPlannerPlan` and `fixReviewFindings` use `presentation: 'stay'`.

`PlanText.savedMs` mirrors `plans::Plan.saved_ms`, from file mtime. Proposals expose their submission time too. Only artifacts saved after this conversation's latest planner start (or the fresh task's creation time) become a current plan card and enable Build. Earlier plans appear in a collapsed disclosure. `useSimpleData` refreshes disk artifacts on Git changes, proposals, related sessions' starts/exits/turn ends and focus, discarding obsolete requests. `changeGroups` supplies Changes and the shared left diff. Before merging, `merge_conflicts` / `mergeConflicts` runs `merges::conflicts` with `git merge-tree --write-tree --name-only --no-messages`; only paths are reported, never opened. Review uses the role presets and merge destination as its base; Options keeps the existing dialog available. `startSimpleReview` retires only settled previous reviewer generations in the slots the selected presets will reuse, so Review again also works with interactive reviewers that remain at a prompt. A changed generation, active turn or worktree cancels that handoff.

`simpleUi.ts` holds only drafts, structured mentions, one queued message, a chat-only Changes tab flag, diff selection and a transient terminal drawer reason (`closed`, `user`, `input`) per worktree. The composer has one terminal toggle beside Send. Both controls use `selectRecipient`, following the current step and giving input waits priority. The resizable drawer hosts exactly that session's `TerminalPane`, switches as the recipient changes, and starts closed. Input requests show the hook message and open the drawer; ending a request closes only a drawer opened for input. View of a planner run no chat claims pins it in the drawer (`terminalSession.pinned`) until Hide, a new input wait, or its record being forgotten; a drawer whose record is gone reads as closed. There are no stage tabs, per-agent terminal cards or disclosure overrides. The timeline follows new items unless the user has scrolled up. `useSimpleData` computes `changeGroups` and its file references once for the chat-only Changes tab, diff and Chat, and supplies their shared worktree scope; App's `SimpleChanges` chooses the default file, the newest hook-reported write still listed, only in Chat; `SimpleDiff` keeps Map / Stories / Changes visible above the diff. Finding references and the latest hook-reported `Edited …` link select that tab. Full Navigation never shows it.

Prompt delivery uses hook-confirmed readiness and generation checks (`simpleComposer.ts::promptReady` / `deliverPrompt`, `session::prompt_ready`). Enter sends (or starts/queues), Shift+Enter adds a newline, and Enter picks a mention while autocomplete is open. Installed hooks gate new/resumed agents. Sessions whose hooks confirm the turn (`authoritative`: working, asking, or a submission not yet acknowledged) queue by default; an unconfirmed state, such as after Esc, never queues, since no hook may report its end; `simpleQueue.ts::followQueuedPrompts` delivers once at a ready prompt even after switching worktrees. Queued messages append with a blank line, can be canceled back to the draft or sent now, and return to drafts on restart, exit or a failed/uncertain write without retrying. Send anyway (protocol 13 `force`) also accepts a hook-confirmed `working` turn, never `needsInput`, a Codex permission request still in its automatic-review grace (`AgentReport.approval_pending` ↔ `approvalPending`) or an agent without authoritative status, since the pasted Enter would answer a dialog; the service enforces this (`session::prompt_forceable`, mirrored by `simpleComposer.ts` `forceable`) along with the authority and generation checks. During an input wait the composer offers Answer in terminal, which opens the drawer. `sendToSession` shares claim/write/release, submission stamps, prompt logging and reply persistence. Drafts and queues are in-memory UI state and never dirty or persist the map. Composer authority is released after writing unless a visible terminal owns it. The shared terminal registry preserves scrollback across drawer, Full and pop-out hosts.

Tool activity remains mirrored through `HookEvent.{tool,target,file_target}`, `status::Activity` and `types.ts::Activity`. Explicit file targets alone link to diffs or pulse map components; command previews and patch bodies are never paths. The newest 50 accepted tool events are retained per generation, merged by sequence in `activity.ts`, and scoped to the selected worktree. Chat's Auto button keeps the existing Light settings, hook checks and ownership controls; Auto stages drive the flow and gates appear as chat prompts.

`npm run smoke:simple` runs disposable fake agents through prompt, reply, plan, new worktree, Build, Review, Fix, conflict check and Merge while Chat stays open. It also checks drawer following, input waits and saved replies. See [Simple verification](../simple-verification.md) for checks requiring a real interactive desktop and provider.
