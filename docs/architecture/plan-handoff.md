### Plan handoff

Codex launches with scoped command networking put additional directories in their
permission configuration before sandbox resolution instead of passing `--add-dir`.
Legacy launches retain existing `sandbox_workspace_write.writable_roots`; named
profiles add `workspace_roots` and apply their existing filesystem rules to them.
This also applies when the planner restarts. Claude continues to use `--add-dir`.

`planning.rs::PlanningScope` distinguishes a project draft from a worktree (`task: null` means the main checkout). Worktree task plans retain their existing files; the main checkout uses `_worktree_main.md`, and project drafts use `_project_draft.md` under `<git-common-dir>/patchbay/plans/`. Planner session identities include that artifact scope, so the same provider preset can plan concurrently in sibling worktrees. The launch metadata, authenticated provider hooks, plan file, briefing, pending proposals, editor drafts, selected provider and story association all carry the same scope. Plan opens on the active worktree; its **New project draft** option has a separate canvas selection and planner. `plan_start` moves the trusted project into the selected task checkout before preparing its briefing.

Build (`lib/planHandoff.ts`) saves its own scope's editor draft and accepts only that scope's plan and assignments. It stops that scope's planner and starts a fresh implementation session. It never copies a project draft over an existing worktree plan. Ordinary worktree creation and attachment inherit no plan.

Creating a worktree from a project draft requires its planner to be stopped. Pending editor changes are saved first. `planning::transfer_draft` copies the plan, pending/applied assignments and file timestamps into an empty destination, rejecting conflicts. Patchbay transfers the conversation, story and any clear boundary, persists that history, then acknowledges source cleanup. A durable receipt permits an exact retry after failure; the source survives until acknowledgement. A replay boundary prevents old source snapshots from recreating transferred history. Plan offers Retry for a pending transfer. Further planning starts a fresh provider session in the destination with its plan, assignments and transferred conversation in the briefing; no live process or provider conversation ID moves between working directories.

Legacy `main.md` and associated proposal/assignment files remain preserved. Migration matches persisted launch/Auto claims against retained legacy session records. One unambiguous owner receives the artifacts only if its destination is empty; otherwise they become a labeled project draft, excluded from worktree Chat and Build. Migration is repeatable, preserves timestamps, and records completion after copying succeeds. A running legacy provider session must finish or stop before a scoped replacement starts.

Plans remain capped at 64 KiB and atomically written. The editor uses compare-and-save (`plans::write_if`), keeping unsaved edits per project and planning scope. Planner sessions receive `PATCHBAY_PLAN_FILE` and a writable plans directory. Implementation briefings include their own saved plan and matching assignments, plus peers and task context. Provider-specific permission handling and context budgets remain in core.

Claude’s opt-in status integration also captures native plans from `ExitPlanMode` hook payloads (`agent_hooks::plan_signal`), without reading provider-supplied paths or approving its dialog. `PreToolUse`/`PermissionRequest` capture a presented plan; `PostToolUse` records approval. A later turn event withdraws an unapproved presentation, restoring the previous plan only if the presented text is still current; editor changes are preserved. `plans::capture`/`withdraw` serialize these writes with the plan editor and proposal apply. Status is journaled first, then the hook uses a short bridge timeout so a disconnected desktop cannot hold up Claude. The bridge accepts captures and withdrawals only from a planner and checks its provider conversation to reject nested runs; subagent events are ignored. Repeated captures of unchanged text retain applied assignments.
