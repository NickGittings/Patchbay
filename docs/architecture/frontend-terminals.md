### Frontend terminals

`lib/terminals.ts` keeps one long-lived xterm instance per session id in a module-level registry and re-parents its DOM element on `attach`, so scrollback survives tab switches and restarts. When a run starts or exits, `restoreModes` undoes the modes a killed TUI left on and clears from the cursor down, so the next run doesn't draw over the dead TUI's input box and status lines; lines above the cursor stay in scrollback. `lib/sessions.ts` applies backend `TerminalEvent`s to both the store (running/exit code → node health) and the xterm, skipping bytes already covered by a snapshot (`seq`/`generation`). `hydrateSession` buffers live events, replays `terminal_snapshot`, then drains the buffer. `components/TerminalPane.tsx` is the shared xterm host used by the dock and pop-out tiles.

`lib/display.ts` `terminalStatus` turns a terminal's kind and `SessionState` (including `status`) into a health class, label and detail used by node chips, dock tabs, grid tiles, inspector rows and planner tabs (`components/status/StatusLabel.tsx`). A finished review, an input request or a failure asks for attention (`unseenSince`) until a focused window shows the session on screen (`TerminalPane` calls `terminal_seen` only while an `IntersectionObserver` sees the pane with a nonzero area, since collapsed panels, hidden tabs and scrolled-away tiles stay mounted; a `ResizeObserver`, focus and visibility changes re-observe the pane, because the intersection ratio doesn't change when a pane grows from or shrinks to zero size). Components showing relative times call `useClockTick` (`lib/clock.ts`) to re-render every 10s. `lib/attention.ts` ranks what wants the user (needs input > failed > not responding > review) for the Activity panel's `AttentionMenu` and per-component `AttentionPill`s (both counting extension-started terminals, `componentTerminals`); `revealTerminal` opens the planner tab (`planActive`, UI only), the Navigation dock for extension terminals, or the Implementation tile.

`lib/notifications.ts` follows all projects' and worktrees' agent sessions and Auto runs in the main window only. New review/needsInput reports (including a newer sinceMs in the same state) and unstopped failed exits produce a 750 ms batch. Turn ends (review) of sessions an unfinished Auto run tracks (`AutoRun.sessionId`, `laneSessions`; running, paused or waiting on you) don't alert while the run owns them. Auto pauses and tracked sessions' input requests also stay silent when their project and worktree are active and the main window is focused; failures still alert. Pauses observed there advance the Auto watermark without being delivered, so switching away doesn't replay them. Auto runs alert when they newly want the user, as `attention.ts` `autoAttentionItems` lists them (waiting on you, including the merge gate, and automatic pauses under the needsInput preference; failed under failed), once per pause (a watermark of run, status, stage, wait and pause kind per worktree; runs already in such a state when the follower starts, a project's tab opens or the workspace restores don't alert; a worktree's run is recorded only once the task list holds it, so a pause reached before then still alerts), except input waits, which alert through the agent session that asks. Their links (`NotificationLink.auto`) open the worktree's Auto panel and drop out once the pause ends. Events of sessions whose project isn't open in a tab, or whose identity isn't known yet, wait and are rechecked when identity sources or the open projects change; they alert then if still current. Native notifications are sent when the main window is unfocused (`document.hasFocus()`), including while a pop-out has focus; a granted permission is cached until a send fails, which also lets a revoked grant be asked for again. The `notifications` capability grants only `is-permission-granted`, `request-permission` and `notify`, to the main window only. The settings test (`sendTestNotification`) reports granted, denied or failed (with the error) apart, and its fallback hint shows above any unread links. An in-app copy always retains unread session links across batches until individually viewed or explicitly dismissed; viewing one leaves the others available. Links the follower creates carry their event (`NotificationLink.kind`/`atMs`) and drop out once `isCurrent` no longer holds (seen, resolved, restarted, stopped) or their project closes, checked when sessions, projects, session records, Auto state or the toast change; the alert hides when no link is left. Leads of running or paused Chat teams, including a lead being swapped in (`reset.nextSession`), never alert, since the user is already talking to them: `sessionIdentity` marks them `chatLead` (`chatIdentity.ts` `leadsActiveTeam`), and the follower drops their events when queued and at flush and prunes their links, also when only `useChatTeams` changes. A stopped or complete team's former lead alerts like any agent. Session alerts name the agent and nothing more (`describe`): the title is its role (`chatRole`'s Builder for Chat workers, else `sessionOwner`) and what happened ("Builder finished"); the body is its name, provider and worktree, each once, plus only the input wait's reason or a failure's exit code, cut to one line by `oneLine`. The prompt is never shown, since a Chat worker's prompt is its whole assignment. Auto pause reasons are cut the same way. Each toast link carries that title as `NotificationLink.heading` and the body as its message, clamped to two lines, with a plain View button; cards slide in from their corner's edge and leave the same way (a cross-fade under reduced motion). Worktree titles use `shortTitle`, and merge-gate alerts omit the redundant approval reason. Link labels add the terminal or lane name and worktree to the owner; toast messages name the project only while another one is active (`notificationLinkLabel`), while native bodies always name it. First hydration and successful exits are ignored. Timestamps must be newer than the follower start and seenMs; per-session, per-kind watermarks of delivered timestamps prevent replay. activeSession alone does not suppress alerts: seenMs acknowledges visibility. A shared `sessionIdentity` lookup (`NotificationIdentity`) prefers records, then runtime terminals, then sessionMetadata and project terminals (including task roots and reserved agent scopes); `sessionMetadata.version` changes whenever an entry is added, changed or removed, so followers notice overwritten identities. Toast cards (`Toast.tsx`) appear in the corner `NotificationSettings.toastPosition` picks; `auto` (`notificationToast.ts` `toastPlacement`) is top right in Chat, so the composer stays clear, and bottom right above the footer otherwise. Other corners are fixed over the workspace, placed from the `--top-bar-height`, `--rail-width` and `--footer-height` chrome variables, and stack below the top bar so its menus stay on top. The position stays editable while notifications are off, since app messages still toast. Global notification preferences live in workspace settings, never patchbay.json or dirty; each restored field must pass its validator (`lib/notificationSettings.ts` `VALID`), and changes made while the workspace restores win field by field (`mergeRestoredNotifications`) and are saved once it ends. Rust Workspace.settings is opaque JSON mirrored by WorkspaceDocument.settings in types.ts.

`components/UnifiedSearch.tsx` lists running agents from every project open in a tab and every worktree once a query is typed (`lib/agentSearch.ts`), above Files with `Cmd+P` and below Commands with `Cmd+Shift+P`; pop-outs stay files-only. Every query word must match the agent's role, component, name or provider, or its project, worktree or branch. Rows name the worktree opening them reaches, which in Chat can differ from where the agent launched (`terminalChatDestination`), and refresh when what they show changes. After an exact component match, Enter prefers an agent of the open project that the query names in whole words, by its role or terminal name, so file queries such as a provider, component or part of a word keep the first file. When the priority group is settled and empty, Enter takes the first agent. Opening a result goes through `reconnectSession`, which rechecks that the session runs and activates its project before `revealTerminal` switches worktree; the terminal takes focus only if focus didn't move during that wait.
