### Data flow: the frontend owns the project

The backend is stateless with respect to the project map. Terminal processes and their backlogs live in the separate `patchbay-sessiond` helper (`session.rs`), which the desktop reaches through `service::Bridge` (pooled loopback connections, one ordered writer for keystrokes and resizes); the desktop keeps, per open project (`AppState.projects`, keyed by the local project id), core-owned file access, a Git watcher and the active task's worktree (`ProjectAccess { access, watcher, task_root }`): the project's root (chosen in the backend's `open_project` picker) and the external folders the user vouched for (`AccessSnapshot.granted`: folders picked in a backend-run dialog — `add_folder`, `pick_component_folder` — or external folders of a loaded `patchbay.json` that the user allowed in the dialog `open_project` shows; until then those components are "locked", returned in `Opened.locked`). File commands (`list_dir`, `reveal_path`, `resolve_path`) take paths relative to the root and may read only the root plus external component folders on the map that lie within `granted`; the frontend's `sync_roots` (debounced and ordered after component path changes, `App.tsx` and `lib/access.ts`) can narrow that set but never widen it. Grants refresh the current map even when its paths are unchanged; `patchbay://file-access` tells open file trees to retry. Filesystem checks run on snapshots without holding the access lock; the adapter dispatches synchronization, briefing and launch work to blocking workers. All access checks compare canonical paths (so symlinks can't widen them), and no granted folder may contain the project root (`model::check_component_dir`). Every command that takes a `Project` replaces its root with the backend's (`AccessSnapshot::trust`); commands that launch or brief (`terminal_start`, `plan_start`, `component_context`, `plan_context`) also drop locked components (`AccessSnapshot::restrict`), and the git commands (`git_status`, `git_changes`, `git_diff`, `git_review`) skip folders that aren't readable. `rescan_project`/`add_folder` return only what they added (`Added`), which the frontend appends to its current map. The zustand store (`src/store.ts`) holds the map as React Flow `nodes`/`edges`, and `toProject()` rebuilds a full `Project` that is passed to every command that needs it (`terminal_start`, `component_context`, `save_project`, `rescan_project`). `dirty` tracks unsaved edits.

The service outlives the app, so an upgraded build may find one of another `session::PROTOCOL` still running. `Client::ensure` then retires it in its own protocol (`retire_outdated`: the `Hello` handshake and `Request::Shutdown` keep the same wire format in every version, pinned by `retire_wire_format_is_stable`) when it has no running work; otherwise the error reaches the frontend and `TerminalPane` offers "Stop older sessions" (`service_retire` ↔ `serviceRetire`, which ends that work). `patchbay-cli sessions shutdown` retires a service of any version the same way.
