### Worktrees

`tasks.rs` — a task is a named piece of work on its own branch and worktree of the project repo, sharing the map. Tasks are per user, stored in `<git-common-dir>/patchbay/tasks.json` (shared by every worktree, never committed); `list` reconciles `branch`/`missing`/`current` with `git::worktrees`. `create` validates the branch (`check-ref-format`, no leading `-`) and base, then runs `git worktree add [-b]` into a free sibling folder `<repo>-<slug(branch)>` (the webview never picks the path); `attach` takes only a path `git::worktrees` lists; `remove` runs `git worktree remove` without `--force` (git refuses dirty trees) and keeps the branch. `remove_with_sessions` (behind `task_remove`) checks the worktree can go, has the session service stop the task's environments and sessions in every project (`TaskSessions::end_task` → `Request::EndTask`, under the operation lock so none can launch meanwhile), removes it, then forgets those sessions' records, which can't resume without the task; a failed forget doesn't undo the removal. Every window's `reconcileSessions` drops the state of sessions the service has forgotten (`withoutForgotten`). `create` checks the store is readable before running git and removes the new worktree (and branch) again if saving fails. Hot paths look tasks up with `stored` (no `git worktree list`), since `in_worktree` validates the path anyway. `project_in` moves a trusted, restricted `Project` into the task's worktree via `git::in_worktree`, dropping components outside that repo (and failing for required ones); `context_section` tells agents which task, branch and worktree they work in. The adapter's `for_task` looks the task up in the backend store (the webview sends only its id) for `terminal_start`, `plan_start`, `component_context` and `plan_context`, which then use `context::session_spec_for`/`plan_session_spec_for` (task in the session id and briefing file name) with extension sections read from the worktree; `git_status`/`git_changes` take `task`, `git_review`/`git_diff` the worktree path. `task_*` commands take the project id; `task_activate` adds that project's active task worktree to its watcher roots (`ProjectAccess.task_root`). Resuming a task's session re-checks its folders against the task's worktree. Extension terminals and the pop-out file tree still use the open worktree.

Frontend: `tasks`/`activeTask` are per-project UI state (`ProjectState`, never `dirty`) and `newTask` is global; `lib/tasks.ts` loads the list when a project's tab opens (`refreshTasks`), and `followActiveTask` (main window) calls `task_activate` per project, and clears and refreshes Git badges only when a project switches task (not on tab switches). Every terminal list keys sessions with the active task (`TerminalPane`/`ValidationChips` take an explicit `task` override; extension terminals use `null`); `startTerminal(c, t, task?)` defaults to it. Attention lists every task's sessions and `revealTerminal` switches task. `WorktreePicker` lives in the rail's Worktree utility panel in every view and mode (with `copyPlan` while Full's Plan view is shown), the shared worktree switcher, and shows an overview of the Project folder and listed worktrees: labels and branches, attention, About component chips, changed and may-affect components via `git_review`, running terminals, collapsed editable notes, Review and Remove. `NewTaskDialog` ("New worktree": new branch or existing worktree, seeded from highlights, else the selection, by `lib/tasks.ts` `seedNewTask`) lives beside it in `components/tasks/`; Plan also offers "New worktree…". Clicking another worktree's row (outside its controls, chips, path and remove confirmation) switches to it; its title button is the keyboard way in; the trigger marks the active worktree's attention and, separately, other worktrees' (`attention.ts` `worktreeAttention`: terminals that want the user plus other worktrees' finished graph actions not yet seen; the store marks a worktree's actions seen in `seenActivities` in the same update that takes it off screen, however that happens: every store update, `useStore.setState` included, passes through `leaveWorktree`; `taskActions.ts` `unseenFinished` is the one test of a finished, unseen action). The picker shows the active worktree's first sentence (`shortTitle`, which ends a sentence only before a capital, so `e.g.` and `U.S.` stay), truncated by CSS, with its branch in the tooltip. The picker and Build's New task share one per-project read of the repo's worktrees (`lib/mainWorktree.ts`: whether there is a repo, and the main worktree's branch; the picker re-reads it on mount and open, Build reads it only if nobody has (`ensureMainWorktree`), and closing a project drops it). UI text calls these worktrees; internal task types, commands and storage names stay the same. Review always shows the active task's worktree (no picker of its own; a worktree must be added as a task to be reviewed; switching drops the selected file, loaded review and a diff opened from findings) and shows validation chips for any worktree with a task.
