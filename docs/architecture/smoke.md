### Testing and smoke

Rust unit tests live in `#[cfg(test)] mod tests` at the bottom of each core module (`.config/nextest.toml` caps the process-spawning ones). Frontend unit tests (Vitest, node environment) sit beside pure modules as `src/**/*.test.ts` and run in `npm run check`; mock `../store` and Tauri APIs rather than testing components. Values hashed or encoded on both sides (`sessionId`, `componentLabel`) are pinned to the same golden strings in a Rust and a TS test, so change both together. The smoke scripts are the end-to-end checks: in debug builds only, `src-tauri/src/smoke.rs` evaluates `$PATCHBAY_SMOKE_SCRIPT` in every window and exits 0/1 when the script emits `PASS…`/`FAIL…` on `patchbay://smoke-report`; `src/lib/smoke.ts` exposes the store and helpers as `window.__patchbaySmoke` (dev bundles only). Every `smoke:*` entry runs through `scripts/smoke-all.mjs`, which owns the per-script table (fixtures, roots, extension folders): it builds sessiond, the desktop app and the CLI once (the same build `tauri dev` makes), serves one Vite on 1420 (it refuses to start if anything already answers there, so stop `tauri dev` first), and runs scripts one at a time, each in its own process group so an interrupt reaches the app and the launcher still stops its service. `PATCHBAY_SMOKE_PREBUILT` makes the launchers (`smoke.mjs`, `lifecycle.mjs`, `readme-shots.mjs`, sharing `scripts/smoke-lib.mjs`) start `target/debug/patchbay-desktop` instead of `tauri dev`. Smoke runs stay in the background on macOS: `smoke.rs` makes the app `ActivationPolicy::Prohibited` (wry activates the app for every new webview) and disables WebKit's background throttling, without which long waits in `git.js`/`status.js` stall — on the main window, which `setup` builds from `tauri.conf.json` (`create: false`) for that reason, and on pop-outs, which the backend's `window_open` builds. Consequently no smoke window ever has focus (`document.hasFocus()` is false, focus events never fire), so terminal authority claims, focus-driven `terminal_seen` and the Git refresh on focus aren't covered end to end; don't write smoke checks that wait on them. The one exception is `npm run screenshots` (`scripts/readme-shots.mjs` running `smoke/readme.js` on the Northstar demo of `smoke/readme-fixture.sh`): it sets `PATCHBAY_SMOKE_FOREGROUND`, so the app stays a regular one whose window can be raised and captured, `smoke.rs` allows it a longer timeout and forwards the launcher's answers to reports from stdin on `patchbay://smoke-ack` (`reportAndWait`); it loads presets from its state folder's `devices` (with the stand-in Claude) and an empty extensions folder, and copies the shots into `docs/screenshots` only once all of them were captured. Default smoke tests use the tracked portable map and files in `apps/desktop/smoke/fixtures/project`, copied into a fresh temporary Git repository per test; the ignored personal map at the checkout root never affects these runs. Explicit fixture roots keep their own maps. Each script (except the screenshots) runs through `scripts/smoke.mjs`, which gives each run a fresh temporary `PATCHBAY_STATE_DIR` (so no saved workspace or session service leaks between runs or into `~/.patchbay`) and shuts that run's service down afterwards. Never add test hooks that run in release builds.
